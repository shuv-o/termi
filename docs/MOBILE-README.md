# @termi/mobile — Capacitor native shell

Native **iOS** and **Android** apps that wrap the hosted Termi PWA in a WebView —
the mobile equivalent of `../apps/electron`. The server URL is baked at build time;
the app loads the live deployment directly (a "thin remote shell"), so there's no
local web build to bundle.

> **Local terminal is desktop-only.** Mobile cannot spawn a PTY, so this shell is
> remote-only (SSH/SCP/RDP/VNC via the gateway). The `LocalTerminal` UI is already
> gated to Electron and stays hidden here.

## How the server URL is resolved

`../apps/mobile/capacitor.config.ts` → `getRemoteUrl()`, in order:

1. `TERMI_REMOTE_URL` env var (dev / CI)
2. `../apps/mobile/build-config.json` (generated by `npm run config`, gitignored)
3. hardcoded default `https://termi.run`

## Prerequisites

- **iOS:** macOS + Xcode + CocoaPods (`sudo gem install cocoapods`)
- **Android:** Android Studio + JDK 17

## Build & run

From the repo root (or `--workspace=apps/mobile`):

```bash
npm install                       # pulls Capacitor into the workspace

# Bake the server URL + create native projects (run once per platform)
TERMI_REMOTE_URL=https://termi.run npm run mobile:add:ios
TERMI_REMOTE_URL=https://termi.run npm run mobile:add:android

# After config or plugin changes
npm run mobile:sync

# Open the native IDE to run / archive / sign
npm run mobile:open:ios           # → Xcode
npm run mobile:open:android       # → Android Studio
```

Local dev against the dev server (cleartext is auto-enabled for non-https URLs;
the Android emulator reaches the host at `10.0.2.2`):

```bash
TERMI_REMOTE_URL=http://10.0.2.2:22080 npm run mobile:sync
```

## Native integration on the web side

`../apps/web/src/components/pwa/CapacitorBridge.tsx` (mounted in the root layout)
detects the native runtime via the global `window.Capacitor` and:

- themes the status bar to `#0f172a`
- maps the Android hardware **back** button to SPA history (exits at the root)

It uses no `@capacitor/*` import, so it's a no-op in a normal browser/PWA.

## App Store note (guideline 4.2)

Apple rejects pure WebView wrappers. Add genuine native value before submitting —
the natural fit is **native push** via `@capacitor/push-notifications` (APNs/FCM),
reusing the existing monitoring/alerts pipeline. Biometric unlock and the native
share sheet are good secondary additions.

Google Play accepts this as-is; you can also ship the lighter
[TWA path](PWA-TWA.md) for Android instead.
